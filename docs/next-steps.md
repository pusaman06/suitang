## 待办 1：分段 JSON 分级重试（保险，不是 bug）

**症状**：长视频切段时，模型输出的 JSON 数组可能因为 `max_tokens` 被截断（少了 `]`），`parseOutline` 直接抛错，整条大纲失败，用户只能重试。

**现状代码**：
- `src/background/index.ts` 的 `generateOutline`：`callDeepSeek(...)` 之后直接 `parseOutline(response, duration, range, lines)`，失败就 `throw`。
- `src/shared/outline.ts` 的 `parseOutline`：只剥一次代码围栏、`JSON.parse` 一次。

**Bilitato 的做法**（`background.js:6953-7007`，可作为参照）：
1. `ai_json_repair` —— 把模型输出再发回去，让它只修 JSON 不改内容
2. 扩 `max_tokens` 到 8192 重发
3. 换更精简的 prompt

**建议改成三级**（从上到下依次尝试，任一步成功就停）：
1. **修 JSON**：把上次的原始输出发回去，prompt =「下面这段内容本应是 JSON 数组，但格式坏了。只修复格式，不要增删任何条目：<原文>」，`max_tokens` 给 2048
2. **扩预算重发**：原来的 prompt 再发一次，`max_tokens` 从 2048 提到 4096
3. **缩输入重发**：把字幕抽稀一半（比如每 2 行取 1 行）再发，减少输出长度

全失败才抛 `bad-json`，UI 提示「大纲格式出错，可以点重试或换一种方式生成」。

**验收**：`e2e/outline.spec.ts` 加一条 mock 用例——前两次返回坏 JSON（截断的数组），第三次返回好的，断言最终出大纲、且一共发了 3 次请求。

**注意**：每次重试都会多花钱，所以级数别加太多；另外要保证重试时 `outlineRunToken` 校验还在（用户可能中途点了别的）。
